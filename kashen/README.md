# 卡审预检

本地三列预检台。用平台常见限制，加上你自己导入的历史卡审词，检查新文案还会不会踩到同样的问题。

词库、忽略词和文案都保存在这台浏览器里，不会上传。

## 打开

直接用浏览器打开 `index.html`。三列分别是：

1. **卡审词与方案**：提前放好的卡审词、替换写法和以前的驳回原因。
2. **待审文案**：贴上这次要提交的文案。命中的词会在原文里标出来。
3. **修改意见**：改写预览和每条理由。删除线是原文，绿色是已经替上的写法，黄色是还要你确认的词。

第一次打开会带一批常见规则和一段示例文案，用来看效果。真正使用前，把你们账号被驳回过的词和当时的改法导入左边。

## 导入

支持 CSV、JSON，以及一行一条的文本。模板在 `template.csv`。

CSV 表头：

```text
卡审词,替换建议,解决方案,平台,分类,严重程度,处理方式,备注,别名
```

- 处理方式写 `自动`：右侧预览会直接替换，并高亮改动。
- 处理方式写 `确认`：只标黄，并给出建议。短词、品牌名、可能误伤的句子用这个。
- 平台用 `/` 分隔，例如 `抖音/小红书`。写 `通用` 则每个平台都会检查。
- 备注用来记以往真实的驳回原因。

一行一条也可以：

```text
最好 => 更合适 | 绝对化用语 | 抖音 | 绝对化用语 | 高 | 确认 | 2024-03 信息流被拒
```

选「通用」时会检查全部词条。选具体平台时，只检查「通用」加上这个平台的词。例如「秒杀」默认只在抖音、小红书、视频号、快手里提示。

## 忽略词

「最近」「完美日记」这类词放在左下角的忽略词里。卡审词如果落在忽略词内部，就不会报。不要把「最」或「第一」单独入库。

## 检查逻辑

同一处只保留更长的卡审词，所以「最好用」不会再拆成「最好」。英文变体（如 `vx`）按整词匹配，避免打进普通单词。预检不能代替平台终审。
